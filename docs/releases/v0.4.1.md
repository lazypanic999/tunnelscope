# TunnelScope v0.4.1

Alpha maintenance release. The receiver now refuses wildcard binds such as
`0.0.0.0` and `::`; bind to an explicit lab interface address for two-host
tests. This prevents accidental listening on every interface. An explicitly
selected interface can still be reachable from untrusted hosts unless the
network restricts access.

The release also documents the current protocol's security boundaries and
the proposed v0.5 scope. It does not add authentication, encryption or
internet-facing support. The tool still does not discover an exact end-to-end
path MTU or prove a root cause on an unknown network.
