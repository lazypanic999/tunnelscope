# TunnelScope v0.6.0

Alpha release focused on repeated measurements, Linux size feedback and a
bounded workflow that brings sender and receiver evidence together.

## Highlights

- Probe summaries retain per-attempt outcomes and describe the no-ACK
  fraction with a 95% Wilson interval. Explicit size and socket errors are
  excluded from sent-attempt counts. No ACK is not a measured packet-loss rate.
- `compare-fragmentation` repeats the same sizes with Linux no-fragment mode
  and source fragmentation permitted, keeping both runs and source checks.
- `probe` and `search` accept `--observe-icmp` on Linux. UDP error-queue
  observations distinguish local errors, IPv4 fragmentation-needed and IPv6
  Packet Too Big feedback, with quoted probe association when available.
- `diagnose HOST --min MIN --max MAX --output diagnosis.json` runs DF probes,
  fragmentation-permitted probes and adaptive search, producing JSON and
  offline HTML. The workflow is bounded to 100 attempts and 120 seconds of
  configured timeout allowance in one sender direction.
- `correlate` accepts either a probe or a diagnosis report. A diagnosis can
  join one receiver capture to its three runs by run ID and probe ID.
  `--html joined.html` also writes a joined offline view with per-attempt
  timestamps and evidence cases. Wrong-run associations are rejected.

## Install

```sh
python -m pip install --upgrade tunnelscope==0.6.0
tunnelscope --version
```

The package supports Python 3.10 and newer. DF comparisons, ICMP observation
and `diagnose` require Linux support; ordinary loopback probes, receiver
observations and report rendering also work on Windows. New report fields
are additive within schema version 1; existing commands remain available.

## Validation

The test suite covers report pairing, HTML escaping, bounded execution and
output-path checks. Privileged Linux namespace labs cover IPv4/IPv6 size
boundaries, visible and blocked ICMP feedback, and blocked ACK return.
A [two-VM WireGuard test](../validation/two-vm-wireguard.md) validates both
directions and joined reports between independent Ubuntu and Debian guests.
Its 1252/1253-byte UDP payload boundary reflects the configured local
1280-byte WireGuard interface MTU on a VirtualBox host-only underlay.

Release checks on 2026-11-04: the 56-test suite passed on Windows with Python
3.10 and 3.13 (seven platform/privilege skips each), and all 56 tests passed
on Linux with Python 3.12 and privileged namespace tests enabled.
Wheel and source distributions passed `twine check`; clean Windows and Linux
wheel installations passed installed-command, loopback correlation and HTML
asset checks. The installed Linux package also passed the joined diagnosis
workflow check.

## Limits

An observed payload interval is not an independently measured end-to-end
path MTU. Missing ACKs and absent ICMP remain inconclusive. ICMP and receiver
evidence are unauthenticated, timestamps from separate hosts are not compared,
and small ACKs do not prove same-sized reverse delivery. Source fragmentation
being permitted does not prove fragment traversal. The tool remains intended
for controlled environments. Production-like VPN constraints and Kubernetes
pod-path validation remain open.
