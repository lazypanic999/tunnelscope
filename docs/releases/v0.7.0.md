# TunnelScope v0.7.0

Alpha release focused on return-path size evidence and on reports that can be
shared safely as field evidence.

## Highlights

- `--sized-reply` on `receive` (Linux) and on `probe`, `search`,
  `compare-fragmentation` and `diagnose` asks the receiver for a reply of
  exactly the probe's size instead of the fixed 24-byte acknowledgement.
  One sender run can now show that a payload arrived but a same-sized reply
  did not return. Results record `return_status` (`sized_reply_received`,
  `small_ack_only`, `no_reply`) and `reply_bytes`. See
  [same-sized replies](../sized-reply.md).
- `correlate` adds `return_evidence`, separating a reply lost after arrival
  (`receiver_observed_sized_reply_missing`) from a reply the receiver's own
  kernel rejected (`receiver_reply_send_failed`) and from missing receiver
  observations. It does not say where a reply was lost.
- With sized replies, an acknowledged attempt means the size crossed both
  directions, so a search or diagnosis interval reflects the smaller one.
- `sanitize` writes copies of reports with addresses replaced by
  documentation addresses, interface names and hostnames replaced by labels
  and timestamps shifted by one constant per batch. Reports sanitized
  together still correlate with the same per-probe evidence. See
  [sanitize reports](../sanitize.md).
- `show` and the HTML view mark sanitized reports and add return columns.

## Compatibility

Report changes are additive within schema version 1. Sized replies are
opt-in on both sides. A v0.7 sender asks with a marker after the run ID; a
v0.6 receiver ignores it and sends the small acknowledgement, which the
sender records as `small_ack_only`. Probes from v0.6 senders carry no marker
and always get the small acknowledgement. Sized-reply probes need payloads
of at least 36 bytes.

## Install

```sh
python -m pip install --upgrade tunnelscope==0.7.0
tunnelscope --version
```

The package supports Python 3.10 and newer. `receive --sized-reply`, DF
comparisons, ICMP observation and `diagnose` require Linux; the sized-reply
sender, `sanitize`, receiver observations and report rendering also work on
Windows.

## Validation

CI now runs on Linux and Windows with Python 3.10 and 3.12; the Linux jobs
also run the privileged namespace labs. A new
[asymmetric return-path lab](../validation/asymmetric-return.md) routes return
traffic over a 1280-byte link: 1400-byte probes reach the receiver while their
same-sized replies do not, and an ordinary small ACK at the same size still
returns. Sanitization was checked on recorded two-VM WireGuard reports:
sanitized probe/receiver and diagnosis/receiver pairs correlate to the same
outcomes.

Release checks on 2026-11-06 are listed in the release pull request.

## Limits

A missing same-sized reply does not identify where or why it was lost.
Sized replies double the bytes per probe and come from an unauthenticated UDP
responder; use them on controlled paths. `sanitize` replaces values it can
recognize; review copies before sharing. An observed payload interval is not
an independently measured end-to-end path MTU, and missing ACKs and absent
ICMP remain inconclusive. Production-like VPN and further Kubernetes CNI
validation remain open ([#1](https://github.com/lazypanic999/tunnelscope/issues/1),
[#2](https://github.com/lazypanic999/tunnelscope/issues/2)).
