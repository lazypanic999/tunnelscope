# TunnelScope v0.8.0

Alpha release that widens return-path evidence to IPv6 and Windows receivers
and makes real-path field reports easier to contribute.

## Highlights

- `receive --sized-reply` now also runs on Windows. Sized replies are sent with
  `IP_DONTFRAGMENT` or `IPV6_DONTFRAG`, so an oversized reply fails with
  `WSAEMSGSIZE` (10040) instead of being fragmented; the receiver refuses to
  start if the option cannot be set. Receiver reports record the option used
  in `receiver.reply_fragmentation`. See [same-sized replies](../sized-reply.md).
- The asymmetric return-path lab runs over IPv6 with `--family ipv6`. As over
  IPv4, 1400-byte probes reach the receiver while their same-sized replies are
  lost (ICMPv6 Packet Too Big goes to the receiver) or rejected locally, and
  a small ACK at 1400 bytes still returns. CI runs both families. See the
  [validation record](../validation/asymmetric-return.md).
- A [field report guide](../field-reports.md) and issue template describe how
  to collect `diagnose --sized-reply` and receiver reports on a real path,
  sanitize them together and share them.
- CI keeps the JSON printed by every privileged namespace lab as a workflow
  artifact (`lab-output-python-<version>`, 90 days).

## Compatibility

Report changes are additive within schema version 1. The probe protocol is
unchanged from v0.7: a v0.8 sender works with v0.7 receivers, and a v0.7
sender works with a v0.8 receiver, including on Windows.

## Install

```sh
python -m pip install --upgrade tunnelscope==0.8.0
tunnelscope --version
```

The package supports Python 3.10 and newer. `receive --sized-reply` works on
Linux (including WSL2) and Windows. DF comparisons, ICMP observation and
`diagnose` still require Linux.

## Validation

- The full suite runs on Linux and Windows with Python 3.10 and 3.12; the
  Linux jobs run the privileged labs, including both asymmetric-lab families.
- On Windows, the real-receiver test returns 64-, 1400- and 8192-byte sized
  replies on loopback, and a local send test turned an oversized 2000-byte
  datagram into `WSAEMSGSIZE` with `IP_DONTFRAGMENT` set.
- The field report guide's commands were run end to end on loopback.

## Not yet validated

- A cross-host run with a Windows receiver: Windows Firewall blocks inbound
  UDP 9471 unless a rule allows it for the test.
- A maintainer dry run of the field report guide on two separate machines.
- Field evidence from production-like VPNs and routed IPv6 outside a lab
  ([#1](https://github.com/lazypanic999/tunnelscope/issues/1),
  [#2](https://github.com/lazypanic999/tunnelscope/issues/2)).

## Limits

A missing same-sized reply does not identify where or why it was lost. The
receiver is an unauthenticated UDP responder intended for controlled paths.
An observed payload interval is not an independently measured end-to-end
path MTU, and missing ACKs and absent ICMP remain inconclusive.
