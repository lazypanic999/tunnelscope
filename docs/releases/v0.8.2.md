# TunnelScope v0.8.2

Patch release for report sanitization consistency, UTC display and reproducible
IPv6 feedback evidence. CLI options and report schema version 1 are unchanged.

## Fixes

- `sanitize` recognizes label-prefixed IPv6 such as `src:fd00:77::1` and
  reserves documentation addresses found in that form. Older versions could
  leave the original address in free text.
- Interface and hostname labels avoid original names in the batch and are
  replaced in one pass, so generated labels are not renamed again. Longer
  known hostnames match before their prefixes. IPv6 scope IDs keep distinct,
  consistent interface labels even without a separate `interface` field.
- ISO timestamps with 1–6 fractional digits parse consistently on Python
  3.10 and newer. Invalid calendar values stay unrecognized text instead of
  aborting sanitization.
- Compact HTML timestamp cells convert nonzero offsets to UTC, matching the
  column label. Full original timestamps remain in tooltips and search.

Before sharing copies produced by an older version, review label-prefixed
IPv6 and regenerate the sanitized batch from the original reports when needed.
Already sanitized files remain protected against accidental re-sanitization.
The command still cannot guarantee removal of arbitrary free-text identifiers;
read the copies before sharing them.

## Validation and workflow

- The [routed IPv6 lab](../validation/ipv6-routed-feedback.md) now compares
  visible and blocked Packet Too Big feedback, records receiver evidence,
  and checks that the blocked size search remains inconclusive. Its recorded
  output and CI artifacts retain the full observations. Offline HTML displays
  both named lab cases.
- The [field report guide](../field-reports.md) separates Linux `diagnose`
  and Windows `probe` filenames and explains how Ctrl+C saves a receiver log.
  New real-process loopback tests exercise collection, joining, sanitization,
  display and rejoining on supported platforms; Linux also checks interrupt
  capture preservation.
- GitHub CI checks Linux and Windows with Python 3.10 and 3.12, with privileged
  IPv4/IPv6 namespace labs on Linux. Independent VPN reports and a Windows
  receiver on a separate host remain open in
  [#2](https://github.com/lazypanic999/tunnelscope/issues/2) and
  [#28](https://github.com/lazypanic999/tunnelscope/issues/28).

## Install

```sh
python -m pip install --upgrade tunnelscope==0.8.2
tunnelscope --version
```

Timeouts and absent ICMP remain inconclusive. These changes do not establish
an exact path MTU or identify the cause of a missing reply on an unknown path.
