# TunnelScope v0.9.0

Share bounded evidence summaries and trace reports back to their declared
producer versions. This alpha release adds offline report improvements and
controlled OpenVPN validation; it does not add peer authentication or claim
automatic root-cause diagnosis. The UDP protocol and report schema version 1
remain compatible.

## Sharing and report provenance

- `tunnelscope show REPORT --format markdown` produces an issue-ready
  summary, limited to 50 rows and 24,000 ASCII characters. Report values are
  escaped as text, omitted rows are explicit, sanitization metadata is shown,
  and interpretation limits accompany the observations. The source JSON
  remains the full evidence. See [Markdown export](../markdown-reports.md).
- New collectors and offline builders record `tunnelscope_version` and
  immediate `input_versions`. Older inputs remain unknown. Adding receiver
  evidence to an old diagnosis preserves its original producer and records
  the new join separately. These are untrusted metadata claims, not signatures.
  See [producer versions](../report-versions.md).
- Text, HTML and Markdown share observation-table data. The default text
  view supports named lab cases and multiple directions. Grouped cases with
  sized replies retain return status, joined return evidence and ACK-send
  status instead of collapsing them into a sender timeout.

## Controlled OpenVPN evidence

Temporary mutually verified TLS/TUN peers add two reproducible IPv4/UDP
scenarios, with data-channel offload disabled:

- [Routed visible/blocked feedback](../validation/openvpn-routed.md): a
  known 1280-byte receiver LAN produces matched ICMP fragmentation-needed
  feedback through the tunnel; blocking that feedback leaves the search
  inconclusive without an observed interval.
- [Asymmetric return egress](../validation/openvpn-asymmetric-return.md):
  small ACKs return at all tested forward sizes, while larger same-sized
  replies are accepted-but-missing or locally rejected after learned PMTU
  state. All forward probes reach the receiver; the join keeps these cases
  separate. The sized search still reports an inconclusive result.

Both scenarios keep non-secret JSON evidence, verify temporary namespace/key
directory cleanup and run in dedicated Python 3.10/3.12 CI jobs. They use
one kernel and deliberately configured MTUs; they do not establish behavior
on arbitrary production VPNs or measure encapsulation overhead.

## Reliability and delivery

- CLI collection checks missing output directories and directory targets
  before opening a receiver or sending probes. Existing regular-file
  overwrite behavior remains where supported; `diagnose` and `sanitize`
  still require new outputs.
- Offline commands accept UTF-8 BOM and UTF-16/UTF-32 JSON exports, including
  BOM-marked PowerShell redirection. Invalid JSON names its input file;
  malformed diagnosis summary/consistency containers fail cleanly.
- Offline output guards compare filesystem identity, preventing a differently
  named hard link from overwriting a raw input during HTML generation,
  correlation or direction comparison.
- Linux source snapshots preserve Unicode and raw OS-byte interface names.
  HTML displays surrogate-escaped bytes without failing UTF-8 output.
- The delivery matrix verifies installed report workflows with isolated
  imports, including lazily loaded renderers and the packaged logo.
- Retained namespace, WireGuard and OpenVPN CI artifacts include a
  [provenance/hash manifest](../validation/ci-artifacts.md), with source and
  tested commit roles kept distinct. A downloaded WireGuard artifact was
  checked against all 26 recorded JSON hashes during release preparation.

## Install

```sh
python -m pip install --upgrade tunnelscope==0.9.0
tunnelscope --version
tunnelscope show shared/correlation.json --format markdown
```

The Linux/Windows delivery matrix covers Python 3.10 and 3.12. The release
suite has 134 tests; platform-specific and privileged checks require their
documented environment and opt-in flags. Runtime dependencies remain empty.

## Still open

Independent operator VPN reports ([#2](https://github.com/lazypanic999/tunnelscope/issues/2)),
a Windows receiver reached from a separate Linux host
([#28](https://github.com/lazypanic999/tunnelscope/issues/28)), and a
two-machine field-guide dry run remain separate follow-ups. Python 3.13 CI
is a contributor task in [#33](https://github.com/lazypanic999/tunnelscope/issues/33).

Timeouts, absent ICMP and missing receiver observations remain inconclusive
without supporting coverage. A small ACK does not establish same-sized return
delivery; reported size intervals are not independently measured end-to-end
path MTUs. Sanitize and review reports before sharing.
