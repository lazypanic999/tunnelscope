# TunnelScope v0.9.3

Patch release after [v0.9.2](v0.9.2.md), rejecting the wrong sender report
type before creating correlation outputs. Thanks to
[sunxiuguo](https://github.com/sunxiuguo) for
[#66](https://github.com/lazypanic999/tunnelscope/pull/66), addressing
[#62](https://github.com/lazypanic999/tunnelscope/issues/62).

## Keep raw sender inputs distinct from joined evidence

Passing an already joined `probe_receiver_correlation` as the sender input
previously succeeded, producing null sender statuses and misleading legacy
pairing metadata. `correlate_reports` now rejects a present `kind` whose
value is not `probe`, including malformed null/list/object values. The CLI
exits with a short `Error:`, leaves both inputs unchanged and creates neither
the requested JSON nor HTML output.

Legacy probe reports with a genuinely absent `kind` remain accepted. An
explicit null value is not treated as an absent field. Valid probe joins
and the separate CLI diagnosis workflow are unchanged. See the
[receiver guide](../receiver-observations.md).

The regressions use an actual retained correlation as the wrong input,
cover malformed declared kinds through subprocess CLI calls, and compare
valid/legacy results with the stored observations. All 145 tests passed in
independent maintainer runs on native Windows/Python 3.10 (17 expected
platform/opt-in skips) and unprivileged WSL2/Python 3.12 (11 privileged-lab
skips). All six Linux/Windows Python 3.10/3.12/3.13 delivery jobs and the
dedicated WireGuard/OpenVPN checks passed for the contributor's exact head.

## Retain the receiver's local IPv6 scope

New receiver captures also retain `receiver.scope_id` when the bound IPv6
socket has a nonzero numeric scope. IPv4 and zero-scope IPv6 output are
unchanged. Sanitization preserves this local metadata; equal numbers on
different hosts do not identify the same link or authenticate an endpoint.
The original v0.9.1 validation captures predate this addition.

Thanks to [HarshRajSinghania](https://github.com/HarshRajSinghania) for
[#67](https://github.com/lazypanic999/tunnelscope/pull/67). The maintainer
limited the final diff to receiver metadata, clarified the historical
record and verified that sender/search/ICMP/budget behavior was preserved.
Three additional scoped/zero-scope/IPv4 tests and a sanitization assertion
passed on Windows and Linux, with all six delivery jobs and VPN checks.

## Install and retained evidence

```sh
python -m pip install --upgrade tunnelscope==0.9.3
tunnelscope --version
```

The source-distribution test gate introduced in v0.9.2 remains in place.
Existing [native Windows validation records](../validation/windows-wsl2-receiver.md)
retain the v0.9.1 producer used for their measurements, including the
[IPv6 link-local](../validation/windows-wsl2-receiver-ipv6.md) and
[oversized reply](../validation/windows-oversized-replies.md) runs.
This patch changes no schema, wire protocol, dependencies or network settings.
Independent operator VPN and physical multi-host evidence remain separate work.
